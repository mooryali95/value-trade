# خطة تحسين UI/UX لمنصة وحدة القيمة — 3 مراحل

مرجعية المدارس المعتمدة: Nielsen's 10 Usability Heuristics، *Don't Make Me Think* (Krug)، *Refactoring UI* (Wathan/Schoger)، *About Face* (Cooper) للأنماط الموجّهة للمهام، Material/Apple HIG لأنماط اللمس والحركة، وWCAG 2.2 AA للوصولية.

## ما تم التحقق منه في الكود الحالي (حالة اليوم)
- لا يوجد أي استخدام متبقٍ لـ `h-screen`/`min-h-screen` — تم الانتقال إلى `dvh`.
- يوجد نظام موحّد: `PageHeader` + breadcrumbs، `DataTableControls`، `ConfirmProvider`، `CommandPalette` (⌘K)، `CookieConsent`، `CompanySwitcher`، `EmptyState`/`ErrorState`/`NotFoundBlock`/`LuxurySkeleton`.
- التوكنز البصرية معرّفة في `src/styles.css` عبر `@theme inline`، مع توكنز خاصة مثل `--gold-deep`.
- **21 ملف route** لا يزال يكتب النصوص عبر شروط `lang === "ar" ? … : …` داخل JSX بدل مفاتيح `i18n` — أكبر مصدر تفاوت لغوي حالياً.

## المرحلة 1 — الأساس: نظام بصري ولغوي واحد لا استثناءات
الهدف: إزالة كل مصدر تفاوت بصري/لفظي قبل أي إعادة تصميم. (Heuristic: Consistency & Standards)

1. **تصفير النصوص المضمّنة**: نقل كل نصوص الـ21 ملفاً إلى `src/lib/i18n.tsx` بمفاتيح مُنظّمة بالنطاق (`portfolio.*`, `shariah.*`, `admin.*`)، وإضافة فحص lint يمنع ظهور `lang === "ar"` داخل JSX مستقبلاً.
2. **مقياس تايبوغرافي وتباعد مُقنَّن**: تعريف سلّم عناوين/نصوص محدود (display / h1 / h2 / body / caption / mono-numeric) في `@theme` واستخدامه بدل الأحجام العشوائية مثل `text-[11px]`؛ الأرقام المالية كلها `tabular-nums` بخط واحد.
3. **توكنز الحالة الدلالية**: `--bull` / `--bear` / `--pending` / `--approved` / `--rejected` + مكوّن `StatusBadge` واحد يستهلكها، ومنع أي لون مباشر داخل المكوّنات.
4. **مراجعة RTL/LTR منهجية**: استبدال أي `left/right/ml/mr` بـ `start/end/ms/me`، وتصحيح اتجاه الأيقونات والرسوم (الشارت، الأسهم، breadcrumbs).
5. **حالات المكوّن الأربع لكل قائمة/جدول**: loading (skeleton مطابق للشكل النهائي) / empty (بعمل تالٍ واضح) / error (بإعادة محاولة) / partial — بلا استثناء.

المخرج: لقطات قبل/بعد لكل صفحة عبر Playwright + تقرير تفاوتات مغلق.

## المرحلة 2 — بنية التنقّل والمهام: من "صفحات" إلى "مهام"
الهدف: أن يعرف المستخدم في ثانيتين: أين أنا، ماذا أملك، ما الخطوة التالية. (Krug + Cooper: goal-directed design)

1. **معمارية معلومات واضحة بثلاث طبقات**: 
   - عام: الرئيسية / السوق / الشريعة / القانوني
   - عملي: المحفظة / التداول / التنبيهات
   - إداري (شركة): الأعضاء والأدوار / الطروحات / سجل التدقيق / سجل البريد
   إعادة تجميع `AppShell` على هذا الأساس، وتوضيح مسمّى `/workspace` أو تحويله إلى لوحة KPI فعلية بعنوان صريح.
2. **لوحة معلومات موجّهة بالقرار**: صف KPI (القيمة الصافية، الربح/الخسارة اليوم، أوامر معلّقة، تنبيهات مفعّلة، طروحات بانتظارك) + "ما يحتاج انتباهك" كقائمة إجراءات، لا مجرد أرقام.
3. **تدفّقات المهام الحرجة كمعالجات (wizards)** بخطوات مرقّمة ومراجعة أخيرة: تنفيذ أمر، طرح منتج، دعوة عضو، إعداد تنبيه — مع ملخّص "ما سيحدث" قبل التأكيد.
4. **قوة الجداول**: أعمدة قابلة للفرز/الترتيب، حالة الفلاتر محفوظة في الـURL (قابلة للمشاركة)، ترقيم صفحات ثابت الموضع، وتحويل كامل إلى بطاقات على الموبايل مع الحقل الأهم أولاً.
5. **وضوح الصلاحيات بدل الرفض الصامت**: الأزرار غير المتاحة تظهر مع تلميح يشرح الدور المطلوب (بدل الإخفاء)، و`AccessDenied` يقترح "اطلب الترقية من المالك".
6. **الاسترجاع من الخطأ**: undo عبر toast للعمليات القابلة للتراجع، ورسائل خطأ بصيغة: ما حدث + السبب + ما يفعله المستخدم الآن.

## المرحلة 3 — الصقل والوصولية والقياس
الهدف: إحساس "منصة مالية فاخرة" + مطابقة WCAG 2.2 AA + قياس فعلي للاستخدام.

1. **وصولية AA**: تدقيق تباين لكل توكن في النمطين، `focus-visible` واضح على كل عنصر تفاعلي، `aria-label` لكل زر أيقوني، أهداف لمس ≥44px، حلقة تركيز صحيحة داخل الحوارات والقائمة ⌘K، `<main>` واحد لكل صفحة، وترتيب عناوين هرمي سليم.
2. **حركة هادئة ومقصودة**: منهج حركة موحّد (150–250ms، easing واحد) للانتقالات والقوائم والصفوف الجديدة، مع احترام `prefers-reduced-motion` كاملاً.
3. **الأداء المحسوس**: skeletons مطابقة، prefetch عند hover لروابط التنقّل، تحسين الشارت وتحميل الجداول الكبيرة تدريجياً، والحد من layout shift.
4. **البدايات الفارغة (first-run)**: onboarding قصير للشركة الجديدة (أنشئ شركة → أضف براندات → ادعُ فريقك → أول أمر) مع مؤشر تقدّم.
5. **الصقل التحريري**: توحيد نبرة الكتابة عربي/إنجليزي، عنوان صفحة + وصف + OG لكل مسار، ونصوص أزرار بصيغة الفعل الواضح.
6. **القياس والتحقق**: قائمة اختبار قابلية استخدام لكل مهمة حرجة (زمن الإنجاز، عدد النقرات، نقاط التوقف)، مجموعة لقطات Playwright على 3 أحجام (موبايل/آيباد/سطح مكتب) في اللغتين كخط أساس للانحدار البصري.

## تفاصيل تقنية
- التوكنز والسلّم في `src/styles.css` داخل `@theme inline`؛ لا ألوان مباشرة في المكوّنات.
- مفاتيح i18n مركزية في `src/lib/i18n.tsx` مع تقسيم نطاقات؛ قاعدة ESLint مخصّصة لمنع النص المضمّن.
- استمرار حالة الجداول عبر `search` params في مسارات TanStack (نفس النمط المستخدم في `/portfolio`).
- الحوارات والقوائم تبقى على Radix/shadcn (`ConfirmProvider`, `CommandDialog`) لعدم إعادة بناء إدارة التركيز.
- سكربتات اللقطات تحت `/tmp/browser/` فقط حتى يبقى المستودع نظيفاً.
