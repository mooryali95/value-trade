# خارطة تطوير تجربة وحدة القيمة

## الهدف والنطاق
تطوير واجهة مؤسسية واضحة وفخمة، تبدأ بدقة المحتوى ثم تنظيم الصفحات والأقسام، وتنتهي بتحسين الاستخدام والتحقق من التجربة. الحفاظ على هوية المنصة وعلى عمل الزملاء؛ لا تغيير للدوال أو قاعدة البيانات أو الصلاحيات أو قواعد التداول.

هذه خارطة تنفيذ مرحلية، وليست اعتمادًا للجاهزية التشغيلية أو القانونية. يبدأ العمل بتحليل موثّق، ولا تُعاد كتابة الصفحات أو حذف أقسامها قبل تحديد أثر التغيير واعتماده.

## المرحلة 1 — تحليل النصوص والمحتوى
**الأولوية: أولًا، قبل أي إعادة تصميم.**
- حصر النصوص الظاهرة: عناوين الصفحات والأقسام، وصف الأدوات، الأزرار، الحقول، رسائل التنبيه، الحالات الفارغة والأخطاء، والإفصاحات.
- إعداد قاموس عربي وإنجليزي موحد: أداة مالية، سهم، صندوق، صك، وحدة علامة تجارية، طلب طرح، إدراج، أمر، صفقة، سعر مرجعي، وحكم شرعي.
- مراجعة التوافق بين لغة المنصة العامة والفئات الأربع؛ لا يُستبدل مصطلح «علامة تجارية» حين يكون خاصًا بتلك الفئة فعلًا.
- فصل النصوص التعريفية عن نصوص اتخاذ القرار؛ اختصار التكرار دون إخفاء المخاطر أو المعلومات المالية اللازمة.
- تمييز النصوص التي تحتاج اعتماد المالك: الباقات والأسعار، بيانات الجهة المشغّلة، الوعود التسويقية، والوضع التنظيمي؛ لا اختراع معلومات بديلة.

**التسليم:** سجل محتوى، وقاموس مصطلحات، وجدول «النص الحالي / المشكلة / المقترح / سبب التغيير / جهة الاعتماد».
**شرط الانتقال:** لا تعارض في المصطلحات الأساسية، والنصوص المحتاجة لاعتماد منفصلة عن التعديلات التحريرية الآمنة.

## المرحلة 2 — تحليل الصفحات والأقسام
- جرد الصفحات ضمن مجموعات: عامة، مستثمر، شركة، مراجعة شرعية، إدارة المنصة، حساب وإعدادات، وقانونية.
- لكل صفحة: من يستخدمها؟ ما غرضها؟ ما الإجراء الأساسي؟ ما المعلومات اللازمة قبله؟ أين ينتقل المستخدم بعدها؟
- تحليل كل قسم إلى: ضروري، ثانوي، مكرر، أو يحتاج تحققًا؛ اقتراح إعادة الترتيب دون حذف تلقائي.
- مراجعة الرئيسية: التعريف بالمنصة، السوق، الجمهور، مسارات الانضمام والإدراج، المراجعة الشرعية، الباقات، الأسئلة، والتذييل.
- توثيق حالات كل صفحة: تحميل، بيانات متاحة، لا بيانات، لا نتائج بعد التصفية، خطأ اتصال، وعدم إتاحة الإجراء للحساب.

**التسليم:** خريطة صفحات وأقسام مع الأولويات، وقائمة تعديلات محدودة لكل صفحة، بدل إعادة بناء شاملة.
**شرط الانتقال:** هدف وإجراء أساسي واضحان لكل صفحة، وعدم وجود أقسام متكررة بلا مبرر.

## المرحلة 3 — تحسين مسارات الاستخدام
1. **المستثمر:** السوق ← التصفية بحسب الفئة ← تفاصيل الأداة ومستنداتها ← مساعد المستثمر ← التداول ← متابعة المحفظة والأوامر.
2. **الشركة:** مساحة العمل ← اختيار فئة الأداة ← تعبئة بيانات النشرة وإرفاق المستندات ← مراجعة المدخلات ← متابعة حالة الطلب.
3. **العضو الجديد:** طلب الانضمام ← الدعوة وتسجيل الدخول ← عرض الخطوة التالية بحسب الحالة الفعلية للحساب.
4. **المراجع والإدارة:** قائمة الطلبات ← التفاصيل والمستندات ← القرار والتأكيد ← النتيجة المسجلة.

- تقليل تكرار الدعوات إلى الإجراء، وتوضيح الفرق بين تقديم الطلب، قبوله، تفعيل الحساب، والتمويل.
- جعل حالة المستخدم والخطوة التالية ظاهرتين دون إضافة خطوات تشغيلية غير موجودة.
- تحسين عرض الفلاتر النشطة، عدد النتائج، إزالة التصفية، والعودة من التفاصيل إلى السوق.
- مراجعة رسائل النجاح والفشل بحيث تصف النتيجة الفعلية، خصوصًا قبول الأمر مقابل تنفيذه.

**التسليم:** مخططات رحلة قصيرة، ثم تحسينات واجهة قابلة للمراجعة لمسار واحد في كل دفعة.
**شرط الانتقال:** نجاح السيناريو الأساسي عبر الواجهة، دون تغيير قواعد النظام.

## المرحلة 4 — توحيد العرض المؤسسي
- توحيد تسلسل العناوين، كثافة المعلومات، المسافات، الأزرار، علامات الحالة، وأسلوب عرض الحقول.
- اعتماد صفوف وجداول قابلة للمقارنة للبيانات المالية، مع عرض مناسب للهاتف.
- مراجعة اتجاه العربية، والنصوص الإنجليزية داخلها، والأرقام والعملات والتواريخ والقيم المفقودة.
- الحفاظ على الألوان والخطوط المعتمدة؛ استخدام حركة هادئة لمواضع محددة، لا للأرقام المالية الحية.
- تحسين أقسام الصفحات قبل إضافة أي زخرفة؛ لا إعادة تصميم واسعة للمظهر القائم دون مراجعة مستقلة.

**التسليم:** دليل واجهة موجز وأمثلة معتمدة، ثم تعميمها تدريجيًا دون لمس عمل الزملاء خارج النطاق.

## المرحلة 5 — النماذج والمستندات والحالات
- مراجعة ترتيب حقول طرح الأسهم والصناديق والصكوك ووحدات العلامات التجارية، مع عناوين مجموعات واضحة.
- توضيح الحقول الإلزامية، إظهار الأخطاء قرب الحقول، والمحافظة على المدخلات عند فشل الإرسال قدر الإمكان ضمن السلوك الحالي.
- تحسين قائمة المستندات: اسم الملف، نوعه، حالته، وإجراء فتحه؛ عرض القيود الفعلية الموجودة فقط.
- توحيد حالات التحميل والفراغ والخطأ، مع إجراء مناسب؛ عدم تصوير تعذر الاتصال وكأنه سوق فارغ.
- تحسين قراءة جواب مساعد المستثمر والإفصاح عن حدوده، دون تعديل مصدر الإجابة أو ضوابطه.

**التسليم:** نماذج وحالات أوضح، متوافقة مع التحقق والوظائف الموجودة.

## المرحلة 6 — التحقق والتسليم للفريق
- التحقق من العربية والإنجليزية على الهاتف والكمبيوتر، ومن عدم تداخل النصوص أو تحرك التخطيط أثناء الاستخدام.
- اختبار لوحة المفاتيح، وضوح التركيز، أسماء الأيقونات، تباين النصوص، وتفضيل تقليل الحركة.
- اختبار الرحلات بالحسابات المناسبة والبيانات الفعلية عند إتاحتها؛ لا يُعد الاختبار بحالة فارغة بديلًا للتحقق الكامل.
- توثيق قبل/بعد، الصفحات المتأثرة، وما جرى التحقق منه وما تعذر التحقق منه، وترك ملاحظات واضحة للزملاء.

**شرط الإغلاق:** لا أخطاء جديدة، نجاح الرحلات المختبرة، وتحديد أي عائق خارجي دون الادعاء بأنه محلول.

| الأولى | تحليل المحتوى والصفحات والأقسام | جرد وملاحظات ومقترحات مع ترتيب الأولويات |
| الثانية | النصوص الآمنة والرئيسية والسوق وتفاصيل الأداة | لغة موحدة وتسلسل معلومات أوضح |

## أمور خارج نطاق هذه الخارطة
- إصلاح اتصال بيانات السوق: يُسجّل للزملاء المسؤولين عن الوظائف؛ لا تعدّل الواجهة البيانات للتغطية عليه.
- اختبار وصول البريد الحقيقي: يحتاج عنوان استقبال صالحًا بدل العنوان الذي ارتدت إليه الرسالة سابقًا.
- اعتماد الباقات والبيانات القانونية والترخيص: يحتاج معلومات وقرارًا من المالك، وليس اجتهادًا في التصميم.
- ربط مصادر سوق خارجية أو خدمات جديدة وتغيير قواعد التداول والصلاحيات: مشاريع مستقلة، ليست ضمن تطوير الواجهة.

## التفاصيل التقنية والتعاون
- التغييرات في صفحات العرض ومكوّناتها والنصوص وألوان النظام فقط؛ الحفاظ على عقود الدوال ونماذج البيانات وقواعد التحقق.
- استعمال المكوّنات والرموز الدلالية القائمة، و`MotionReveal` للحركة الاختيارية، مع عدم تحريك القيم المالية الحية.
- توثيق التحليل ودليل العرض داخل `docs/`، والإبقاء على `roadmap.md` كقائمة عمل مختصرة لا كسجل تاريخي.
- فصل كل دفعة حسب الصفحات المتأثرة؛ مراجعة المحتوى الحالي قبل كل تعديل لتجنب استبدال تغييرات الزملاء.
- فحوص الواجهة واختبارات السلوك ذات الصلة قبل إغلاق الدفعة؛ لا تعديل في قاعدة البيانات أو وظائف الخادم.
