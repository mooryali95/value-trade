# خطة الإصلاح الشاملة وجاهزية الانطلاق — منصة وحدة القيمة

مراجعة لكل موديول على حدة: الحالة الفعلية، الفجوات، والعمل المطلوب قبل الإطلاق الحقيقي.
مقسّمة إلى ثلاث موجات قابلة للتعديل والتنفيذ بالترتيب.

---

## أولًا: بطاقة حالة الموديولات

| الموديول | الحالة | الفجوة الحاكمة قبل الإطلاق |
|---|---|---|
| الهوية والدخول (`/auth`, `/request-access`, `join.$slug`) | جاهز | لا توجد شاشة "نسيت كلمة المرور" مكتملة، ولا إعادة إرسال الدعوة |
| الأدوار والصلاحيات (`roles.functions`, `has_role`) | جاهز | مصفوفة الأدوار غير موثّقة في مكان واحد، وبعض الأزرار تُخفى دون رسالة سبب |
| تعدد الشركات (`companies`, `company_members`, switcher) | جاهز | لا حد فعلي مطبّق على 30 براند/شركة، ولا شاشة أعضاء واضحة للحذف/تغيير الدور |
| بيانات السوق (`internal-provider`) | جاهز داخليًا | لا محرك مطابقة أوامر حقيقي؛ التنفيذ فوري بسعر مرجعي |
| التداول والأوامر (`place-order`, `order-mutations`) | جاهز | لا رصيد نقدي مُدار (إيداع/سحب)، ولا حدود مخاطر أو سعر يومي |
| المحفظة (`/portfolio`) | جاهز | لا تصدير CSV، ولا كشف حساب/أرباح محققة تاريخية |
| الشريعة (`/shariah`, `/shariah/review`) | جاهز | لا منع تداول تلقائي عند قرار `non_halal` |
| الطروحات (`company.submit`, `admin.submissions`) | جاهز | لا مرفقات/مستندات مع الطرح، ولا سبب رفض إلزامي |
| الإشعارات والبريد | جاهز | يحتاج نطاق بريد مُوثّق (SPF/DKIM) قبل الإنتاج |
| التدقيق (`/company/audit`) | جاهز | لا تصدير ولا احتفاظ زمني معلن |
| الأمان (RLS, rate-limit, HIBP) | جاهز | يحتاج فحصًا نهائيًا + نشرًا لسريان المفاتيح المُدوَّرة |
| الوصولية و UI | جاهز (0 انتهاكات) | صفحات `/docs/*` تجريبية يجب استثناؤها من الفهرسة |
| SEO والمحتوى العام | جزئي | صفحات الهبوط تفتقد شرحًا تجاريًا و`head()` فريدًا لكل مسار |
| التشغيل والرصد | ناقص | لا لوحة صحة، لا جدولة Cron مُعلنة، لا سياسة نسخ احتياطي مكتوبة |

## الموجة أ — حاصرات الإطلاق (لا نُطلق قبلها)

1. **دورة كلمة المرور والدعوات**
   - استعادة كلمة المرور كاملة (طلب → بريد → تعيين جديد).
   - إعادة إرسال الدعوة وإلغاؤها من `/invitations` مع مهلة صلاحية ظاهرة.

2. **الأموال قبل التداول**
   - رصيد المحفظة يصبح مُدارًا: حركات `cash_ledger` (إيداع/سحب/تسوية أمر) بدل تحديث رقم مباشر.
   - كل أمر يُنشئ حركة مقابلة، والرصيد = مجموع الحركات (مصدر حقيقة واحد).

3. **حاجز الشريعة**
   - قرار `non_halal` يمنع أوامر الشراء على الرمز مباشرة (تحقق على الخادم + رسالة واضحة في `/trade`).

4. **حدود التينانت**
   - تطبيق حد 30 براند/شركة على الخادم مع رسالة عند التجاوز.
   - شاشة أعضاء الشركة: تغيير الدور، إزالة عضو، منع إزالة المالك الأخير.

5. **الأمان النهائي**
   - `security--run_security_scan` + `supabase--linter` بنتيجة صفر حاصرات.
   - `noindex` على `/docs/a11y` و`/docs/states`، واستثناؤها من `sitemap.xml`.

6. **جاهزية البريد**
   - توثيق نطاق الإرسال (SPF/DKIM) وتبديل عنوان المُرسِل من الافتراضي إلى نطاق المنصة.

## الموجة ب — اكتمال المنتج (أسبوع الإطلاق)

7. **الطروحات**: مرفقات مستندات + سبب رفض إلزامي + إشعار لمقدّم الطلب بكل تغيير حالة.
8. **المحفظة**: تصدير CSV للأوامر والمراكز، وكشف أرباح محققة/غير محققة بتاريخ.
9. **التدقيق**: تصدير سجل التدقيق + سياسة احتفاظ معلنة في `SECURITY.md`.
10. **حدود المخاطر**: حد أعلى لقيمة الأمر الواحد، ونطاق سعر يومي (±%) لمنع الأوامر الشاذة.
11. **الصفحة العامة والمحتوى**: `head()` فريد لكل مسار عام، وقسم "كيف تعمل المنصة" + الأسعار/الشروط للشركات.
12. **التشغيل**: صفحة صحة داخلية (طول طابور البريد، فشل الإرسال، آخر تشغيل Cron) + جدولة `/api/public/cron-alerts` موثّقة بمفتاحها.

---

## الموجة ج — ما بعد الإطلاق (متتابع)

13. محرك مطابقة أوامر حقيقي (دفتر أوامر، تنفيذ جزئي) — أكبر بند متبقٍ وظيفيًا.
14. نقل بيانات البراندات من `mock-data.ts` إلى `company_brands` كمصدر حقيقة.
15. لوحات تحليلية للشركة (حجم، ملّاك، تدفق) وتقارير شهرية بالبريد.
16. مسار المزوّد الخارجي (Tadawul/Mubasher) عند الحاجة — البنية موجودة وجاهزة للتبديل.

## قائمة تحقق الانطلاق (Go/No-Go)

- [ ] فحص أمني بصفر حاصرات + linter نظيف
- [ ] 32+ اختبار Vitest أخضر + axe بصفر انتهاكات
- [ ] دورة كاملة مُجرّبة يدويًا: طلب إتاحة → موافقة → دعوة → قبول → أمر → تنبيه → بريد
- [ ] عزل بين شركتين مؤكّد باختبار RLS
- [ ] بريد يُسلَّم من نطاق المنصة (لا نطاق افتراضي)
- [ ] الصفحات القانونية الأربع منشورة ومربوطة في التذييل
- [ ] نشر إنتاجي بعد تدوير المفاتيح، ثم تحقق دخان على الرابط الحقيقي

## ملاحظات تقنية

- كل منطق مالي جديد يُنفَّذ في `createServerFn` بـ`requireSupabaseAuth`، ولا يُحسب رصيد في المتصفح.
- كل جدول جديد في `public` يحتاج `GRANT` + RLS + سياسات في نفس الترحيل.
- المسارات العامة تبقى بدون دوال محمية في الـ`loader`؛ الجلب داخل المكوّن.
- سجل الحوكمة السابق (المراحل 0–4) مؤرشف ويظل مرجع `SECURITY.md`؛ هذه الخطة تكمله ولا تُلغيه.
