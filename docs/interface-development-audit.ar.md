# تحليل وتطوير واجهة وحدة القيمة

## نطاق العمل وحدود الإثبات
هذا سجل تحليل للواجهة، وليس اعتمادًا تشغيليًا أو قانونيًا. لا تغييرات في الدوال أو البيانات أو الصلاحيات أو قواعد التداول. دعم فئة مالية لا يعني وجود أدوات مدرجة منها. لا حذف تلقائي لأقسام الزملاء.

## قاموس المحتوى العربي والإنجليزي
| العربية | English | الاستخدام |
|---|---|---|
| أداة مالية | Financial instrument | الاسم العام الذي يشمل الفئات المعتمدة |
| أسهم | Stocks | فئة الأسهم، لا تُستخدم لوصف كل الأدوات |
| صناديق | Funds | فئة الصناديق |
| صكوك | Sukuk | فئة الصكوك |
| وحدات علامة تجارية | Brand units | الفئة الخاصة بوحدات العلامات، لا تعني تلقائيًا ملكية أسهم الشركة |
| طلب انضمام | Access request | طلب عضوية للمستثمر أو الشركة، ليس طلب إدراج |
| طلب إدراج | Listing submission | تقديم الأداة للمراجعة، لا إعلان بدء تداولها |
| نشرة الإصدار | Prospectus | مستند يحدد خصائص الطرح والحقوق والمخاطر |
| أمر | Order | طلب شراء أو بيع، قد ينتظر أو ينفذ جزئيًا |
| صفقة منفذة | Executed trade | تنفيذ فعلي، وليس مجرد قبول الأمر |
| سعر مرجعي | Reference price | قيمة مرجعية موضحة، لا تُسمّى آخر صفقة إذا لم يحدث تنفيذ |

## سجل النصوص وقرارات التحرير
| المصدر | المشكلة المثبتة | المقترح | الاعتماد |
|---|---|---|---|
| `heroHeadline`, `heroSub`, `authTagline` | تعريف عام محصور بالعلامات رغم اعتماد أربع فئات | اسم المنصة عنوانًا، ووصف سوق الأدوات والفئات دون وعد بتوافر إدراجات | تحرير آمن |
| `ctaPrimary` | «ادخل السوق» يمكن فهمها كتفعيل فوري | «تصفّح السوق» | تحرير آمن |

| `u_co1T` | طلب انضمام شركة مسمّى طلب إدراج | «طلب انضمام الشركة» | تحرير آمن |
| `u_co2T`, `u_co2D`, `u_audCompaniesDesc` | رحلة تقديم عامة بصياغة علامة فقط | صياغة أداة ومستندات، مع الحفاظ على مصطلح العلامة في إدارة قائمتها | تحرير آمن |
| `plansTitle`, `plansSub` | تدقيق سابق اعتبر الجمهور غير محدد، وهذا غير صحيح | النص يذكر الشركات فعلًا؛ لا تغيير للخطط أو قيمها | يحتاج المالك لاعتماد العرض التجاري، لا تعديل الآن |
| الشروط والترخيص والتواصل | لا يجوز استنتاج اعتماد تنظيمي أو اختراع بيانات | إبقاء الصياغات القائمة وطلب المعلومات المعتمدة عند الحاجة | المالك/مراجع قانوني |
| رسائل أوامر التداول | يجب التفريق بين قبول الأمر والتنفيذ | الإبقاء على `describeOrderOutcome`؛ لا تغيير للمحرك أو نتائجه | السلوك الحالي |

## جرد الصفحات والأقسام
| المجموعة والصفحات | الهدف والإجراء الأساسي | الأقسام والحالات التي تُراجع |
|---|---|---|
| العامة: `/` | تعريف نطاق المنصة، ثم تصفح السوق أو طلب الانضمام | مقدمة، لوحة سوق، الجمهور، المساران، المراجعة الشرعية، المبادئ، الأسعار، الأسئلة، الخاتمة؛ لا حذف لأي قسم |
| `/market` | استعراض أدوات مدرجة ومقارنتها | ملخص، فئات، بحث، قطاع، فرز، نتائج، تفاصيل؛ تفريق الاتصال الفاشل والسوق الفارغ والبحث بلا نتائج |
| `/market/$slug`, `/company/$id` | فحص الأداة والجهة المصدرة | الفئة، السعر، الحكم، بيانات التداول، ملف الجهة، مساعد المستثمر؛ لا حقوق اقتصادية مخترعة |
| `/request-access`, `/auth`, `/auth/update-password`, `/invite/$token`, `/join/$slug` | انضمام أو دخول آمن وعودة للوجهة | اختيار نوع الطلب، حقول، مرجع، قرار، دعوة، رابط منتهي، استعادة؛ لا تعديل لإعدادات الدخول |
| `/portfolio`, `/portfolio/realized`, `/trade/$symbol` | متابعة المال والأوامر وإرسال أمر | مؤشرات، مراكز، أوامر، تصفية، تصدير، دفتر، إدخال، تأكيد، نتيجة؛ الأرقام لا تتحرك للزينة |
| `/workspace`, `/company/settings`, `/company/submit`, `/company/submissions`, `/company/audit`, `/invitations` | تقديم وإدارة أدوات الشركة وفريقها | شركة نشطة، قائمة أدوات، أعضاء، دعوات، اختيار فئة، بيانات طرح، مراجعة، إرفاق، تتبع وقرار |
| `/access-requests`, `/shariah/review`, `/admin/submissions`, `/admin/companies`, `/admin/investors` | مراجعة الطلب المناسب واتخاذ قرار | قوائم، فلاتر، تفاصيل، مستندات، تأكيد، ملاحظات؛ لا تعديل لصلاحية الإجراء |
| `/admin/email-log`, `/admin/health`, `/admin/ops`, `/admin/ops/$id` | متابعة التشغيل | نتائج وفشل ومحاولة جديدة؛ عدم تحويل غياب البيانات إلى صفر |
| `/settings/notifications`, `/unsubscribe` | إدارة تفضيلات الإشعارات | حفظ، حالة، نجاح/فشل؛ لا تغيير لخدمة الإرسال |
| `/shariah`, `/legal/*`, `/docs/a11y`, `/docs/states` | مراجعة الإفصاحات والمرجع | عناوين وأقسام وروابط ومحتوى؛ مراجعة النص القانوني لدى المختص |

## ترتيب الأقسام دون حذف
الرئيسية تحتفظ بجميع أقسامها. تُعطى الأولوية لتعريف المنصة واختيار الوجهة، ثم تمييز مسار المستثمر والشركة، ثم المعلومات الداعمة. تُترك دعوات الانضمام الرئيسية في بطاقات الجمهور والخاتمة، وتقل المنافسة بينها في المقدمة. تكرار الإفصاح الشرعي أو المالي لا يُحذف لمجرد أنه متكرر.

## الرحلات المستهدفة
- المستثمر: تصفح ← فئة وبحث ← تفاصيل وحقوق موثقة في نشرة ← سؤال المساعد عند الدخول ← أمر وتأكيد ← نتيجة فعلية ومحفظة.
- الشركة: شركة وفئة ← بيانات الطرح ← مراجعة دون قص القيم الطويلة ← إرسال ← إرفاق المستندات ← متابعة الطلب. الإرفاق بعد إنشاء الطلب هو السلوك الحالي، وليس مرحلة مكتملة قبل الإرسال.
- العضو: طلب ← قرار ودعوة ← تعيين كلمة مرور ← حالة التفعيل والتمويل الفعلية، وليس وعد تفعيل تلقائي.
- المراجع/الإدارة: قائمة ← تفاصيل ومستندات ← قرار مؤكد ← قراءة النتيجة المسجلة. التحقق الحقيقي يحتاج حسابًا مناسبًا.

## دليل العرض والتعاون
- النصوص العامة تتبع قاموس المصطلحات؛ لا استبدال شامل لكلمة «علامة» في الصفحات الخاصة بالعلامات.
- عناوين وحقول قابلة للقراءة، اتجاه مستقل للأسماء والرموز الإنجليزية، والتفاف للمستندات والقيم الطويلة بدل قصها.
- حالات تحميل وخطأ وفراغ منفصلة، مع محاولة جديدة أو إزالة فلاتر أو وجهة مناسبة.
- الأزرار الجديدة أو المعدلة تستخدم مكوّن Button القائم؛ الألوان من الرموز الدلالية فقط.
- الحركة اختيارية ومؤسسية، متوافقة مع تقليل الحركة، لا تحريك للبيانات المالية الحية.
- إجراء كل تغيير في صفحة العرض فقط مع الحفاظ على استدعاءات الدوال والتحقق الحالي.

## متطلبات إغلاق التحقق
1. اختبار النص والاتجاه والتخطيط بالعربية والإنجليزية على الهاتف والكمبيوتر.
2. فحص البحث والفلاتر والرجوع والحالات الفعلية دون بيانات وهمية.
3. فحص الرحلات الخاصة بحسابات مناسبة؛ لا تُعتبر صفحة الدخول أو السوق الفارغ تحققًا لتقديم أداة أو أمر.
4. توثيق ما تعذر بسبب الوصول إلى الخدمة أو اعتماد المالك؛ لا الادعاء بإنجاز كامل أو جاهزية إطلاق.
